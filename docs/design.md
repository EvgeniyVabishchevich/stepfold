# Дизайн

Контекст для макетов. Его читает дизайнер, человек или агент, перед любой работой в редакторе макетов. Решения записываются сюда с датой.

## Продукт

Stepfold — мобильное приложение (Android и iOS, Flutter). Шаги за день копятся в запас. Запас тратится на главы прогрессий: истории, путешествия, коллекции. За пройденную прогрессию дают награду. Сценарии и экраны — в [product.md](product.md).

Интерфейс опирается на Material 3 и использует свои компоненты Stepfold. Визуальное направление для нового UI-кита — «Рельефная поверхность», вариант B (решено 24.11.2026).

## Вкус

- Серьёзно, но уютно.
- Нельзя: яркое и насыщенное, навязчивые шрифты с засечками, стилизация под старину, мультяшность.
- Один главный элемент на экране, остальное тише.
- Розовый — желанный цвет.

## Рельефная поверхность — решено 24.11.2026

- **Три уровня.** Фон экрана — базовый тон. Карточки отделяются оттенком поверхности и мягкой тенью. Для текста и полосы прогресса используется более светлая подложка `relief.color.progressSurface` со слабой внутренней тенью. Подсвеченная верхняя кромка помогает отделить карточку в тёмной теме. Самый заметный рельеф получает главный блок экрана.
- **Форма.** В эталоне главная карточка имеет радиус 28, углубление — 16, основная кнопка — капсульную форму. Обычные поверхности, границы, тени, радиусы и состояния задаются по ролям в ките. Направление света одинаково у карточки и кнопки.
- **Действия.** Главное действие — розовая кнопка с нижней кромкой. При нажатии кнопка опускается, кромка скрывается, заливка меняет тон. Второстепенное действие использует спокойную тональную подложку, текстовое действие — цвет текста. Высота зоны касания — минимум 48 логических единиц, эталон основной кнопки — 52. Во время загрузки кнопка сохраняет размер. Выбранное состояние, ошибки и долг обозначаем также формой, подписью или значком.
- **Длинные значения.** Счётчики используют табличные цифры и разряды с неразрывными пробелами, например «100 000». Число показываем целиком. Единица, подпись и соседний показатель могут перейти на следующую строку. Длинные названия и подписи переносятся, блоки растут по содержимому, экран прокручивается. При узком экране или крупном системном тексте соседние колонки становятся вертикальными. Проверяем макеты от 320 логических единиц, скролл и системный размер текста — в реализации. Минимальный контраст текста — 4,5:1 в обеих темах.

Принципы тонального и теневого разделения поверхностей взяты из [Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3). Размер зоны касания и явное состояние нажатия сверены с [Android Developers](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) и [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/buttons).

## Редактор — Penpot (решено 16.11.2026)

- Основной файл «Stepfold»: [UI Kit · Рельеф](https://design.penpot.app/?screen=workspace&team-id=51f2d744-23b9-8138-8008-f493fc469970&file-id=51f2d744-23b9-8138-8008-f4954a2e0a1c&page-id=03e6710d-2b25-8049-8008-fef1b91dffc3), [Сегодня · Рельеф](https://design.penpot.app/?screen=workspace&team-id=51f2d744-23b9-8138-8008-f493fc469970&file-id=51f2d744-23b9-8138-8008-f4954a2e0a1c&page-id=03e6710d-2b25-8049-8008-fef1b9249678), [Нижняя панель · Stepfold](https://design.penpot.app/?screen=workspace&team-id=51f2d744-23b9-8138-8008-f493fc469970&file-id=51f2d744-23b9-8138-8008-f4954a2e0a1c&page-id=03e6710d-2b25-8049-8008-fef1b925dde9). Именованная версия «Рельефный UI Kit · принято» (24.11.2026).
- Работа через сервер MCP `penpot`. Он видит только открытую страницу активной вкладки, поэтому файл должен быть открыт в браузере и подключён (**File → MCP Server → Connect**).
- Токены рельефного кита — наборы `relief/global`, `relief/light`, `relief/dark`. Во Flutter роли рельефа собраны в `KitRelief`.
- Ограничения: tabular figures (tnum) в Penpot не включить, их задаёт тема в коде (`FontFeature.tabularFigures()`). Тёмная витрина собирается из отсоединённых копий: тема у файла одна на всех.
- Сохранность: автосохранения хранятся 7 дней, именованные версии — бессрочно. В конце каждого шага сохраняем именованную версию, на крупных шагах выгружаем `.penpot`.

Было: Figma (09.11). Сменили, потому что бесплатный тариф Starter даёт 6–20 вызовов MCP в месяц, а на кит и экраны их нужно десятки. Старый файл остаётся архивом: https://www.figma.com/design/2CPRmpQSlb9zYBcuX7lBL2

## Иконки — обновлено 24.11.2026

- Набор Phosphor (`@phosphor-icons/core` 2.1.1, MIT). В проект кладём готовые SVG, пакет `phosphor_flutter` не берём: он не обновлялся с 2024 года.
- Нижняя навигация использует вариант A с авторскими SVG Stepfold. Активную вкладку выделяют углубление, акцентный цвет и вес подписи.
- Вкладки делят ширину поровну. Между краем зоны касания и подписью, а также между значком и подписью — 4 логические единицы. При увеличенном системном тексте подписи переносятся, значки остаются на одной линии.
- Во Flutter под подписью оставляем 6 логических единиц внутри вкладки и 2 внутри панели. Высота зоны касания вкладки — от 48. Нижний системный отступ берём из безопасной зоны устройства.

Было: Material Symbols Rounded — не понравились. Сравнивали Phosphor, Lucide и Tabler; у Альбома кубок заменили на `cards`: Альбом — коллекция, а не награда.

## Порядок работы

Гайдлайны → токены → UI-кит → экраны. Экран собирается только из компонентов и переменных кита.

Кит растёт вместе с экранами (решено 16.11.2026). Сначала — основа: токены и компоненты, которые есть почти везде ([бриф](screens/ui-kit.md)). Каждый экранный шаг сначала добавляет в кит то, чего не хватает этому экрану, и только потом собирает экран. Компоненты не придумываем заранее, без экрана, на котором они нужны.

Перед экраном пишется бриф `docs/screens/<экран>.md`:
- цель экрана;
- данные из `domain/`;
- все состояния: данные, пусто, загрузка, ошибка;
- действия пользователя;
- крайние случаи.

Макет сверяется с брифом. Если по ходу правок что-то поменялось, итог записывается в бриф.
