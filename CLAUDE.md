# Stepfold

Flutter-приложение, в котором шаги открывают главы, коллекции и целый мир: каталог прогрессий, выбор цели, история, сводка за неделю, напоминания. Подписка Pro, реклама в бесплатной версии, вход через OAuth 2.

Каждая внешняя область (геолокация, база, карта, уведомления, реклама, подписка, вход, пуш, платежи, отчёты о падениях) спрятана за интерфейсом и имеет фейк и **две реализации**, которые переключаются в меню разработчика. Цель — архитектура, в которой провайдера легко заменить, и сравнение инструментов одной области.

## Правила кода

- Слои сверху: `lib/app/`, `lib/domain/`, `lib/data/`, `lib/ui/`. Подробно — [architecture.md](docs/architecture.md#структура).
- `domain/` импортирует только Dart (и `clock`). Ни `flutter`, ни `dio`, ни SDK.
- Интерфейсы — в `domain/repositories/`, реализации — в `data/repositories/<область>/`: `fake_…`, `<вариант1>_…`, `<вариант2>_…`.
- `ui/` знает только `domain/`. Блок получает интерфейс в конструкторе.
- Конкретные реализации видит только `app/` (корень композиции).
- Ошибки — sealed-исключения на область (`PurchaseFailure` и т. д.). `data/` переводит в них ошибки SDK, блок разбирает `switch`. На каждый путь ошибки в блоке — тест.
- Состояние — только BLoC. DI — через конструктор и `RepositoryProvider`, без get_it. Навигация — go_router.
- «Сейчас» — через `clock`, не `DateTime.now()` в логике.
- Линтер — very_good_analysis, анализатор чистый перед коммитом.
- В публичный код — только тестовые ID рекламы и тестовые ключи платежей.

## Тесты

- Контрактный набор на каждый интерфейс — функция с фабрикой реализации, гоняется на фейке и обеих реализациях.
- `bloc_test` на блоки, `clock` для времени, drift в памяти для базы.
- Подробно — [architecture.md](docs/architecture.md#план-тестов).

## Как работаем

- **Один заход — один шаг этапа.** Этапы A–F — в [architecture.md](docs/architecture.md#порядок-работ--решено-0911).
- Цикл области: интерфейс → фейк → реализация 1 → реализация 2 → контрактные тесты → запись решения в документы.
- Сервер — пока `FakeWalksApi` в памяти. Настоящий сервер — в самом конце, на другом языке.
- Коммиты — только когда попросят.
- Если существует `CLAUDE.local.md`, прочитай его: там правила, как здесь распределена работа между человеком и агентом.

## Этап A — первый запуск

Проекта Flutter ещё нет, только документы.

1. `flutter create --org <уточнить> --project-name walks .` в этой папке.
2. В `.gitignore` добавить `CLAUDE.local.md` **до** первого `git add`.
3. `very_good_analysis`, пустые папки слоёв по [структуре](docs/architecture.md#структура).
4. Дальше — по этапу A в [architecture.md](docs/architecture.md#порядок-работ--решено-0911), но **сначала этап 0**: вопросы 1–9 из [open-questions.md](docs/open-questions.md).
